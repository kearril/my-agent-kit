# Feature Specification: Entry Detail Metadata Card Panel (条目详情页独立元数据卡片面板)

**Feature Branch**: `004-entry-metadata-panel`

**Created**: 2026-08-29

**Status**: Draft

**Input**: User description: "我现在需要重构条目详情页的界面。我的需求是，将详情页的一些元数据，如链接，tag等等之类的东西展示改为一个独立的卡片面板，不与正文放在一起。"

## Clarifications

### Session 2026-08-29

- Q: 在保持正文卷宗严格水平居中的前提下，独立的元数据卡片面板应采用何种空间结构与排布形式？ → A: 正文卷宗必须保持严格水平居中且仅承载纯正文内容（大标题、摘要提要、Markdown 渲染正文）；所有非正文元数据（分类徽章、标本编号、首次收录/最近修订时间戳、标签矩阵、外部资源链接、双向关联及反向引用）全部移入独立的元数据卡片面板中；在桌面宽屏视口下，该卡片面板置于居中正文左侧的外边缘空白区域。
- Q: 在窄屏与移动设备（视口宽度 $< 1200\text{px}$）且左侧空白不足以容纳侧边面板时，独立的元数据卡片面板应以何种方式在页面流中呈现？ → A: 采用正文上方折叠抽屉/手风琴卡片形态（Collapsible Dossier Accordion），在正文上方以紧凑卡片呈现基础标牌信息，支持点击展开/收起查看完整标签、外链与关联图谱，兼顾移动端首屏紧凑度与元数据的高效可达。
- Q: 在桌面端左侧外边缘的展示中，元数据卡片面板应采用“单张一体化工坊档案大卡”还是“多张独立小卡片垂直堆叠”的视觉形态？ → A: 采用单张一体化工坊档案大卡（Unified Dossier Ledger）形态，整体为一个独立的完整大卡片容器，内部使用工坊虚线或印章标牌清晰分隔各功能区块（标本身份 → 标签矩阵 → 外链资源 → 关联图谱），保持极佳的视觉聚合度与紧凑版式。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 独立元数据卡片面板的结构与信息呈现 (Priority: P1)

作为一名在 Paracosm Garden 中查阅条目详情的访客，我希望在进入任意公开条目详情页（`/entries/<slug>/`）时，能够看到水平居中的纯净正文卷宗，以及置于居中正文左侧外边缘空白区域的“单张一体化标本元数据档案大卡（Unified Dossier Ledger）”，卡片中集中且有序地收纳该条目的分类徽章、标本编号、收录/修订时间、标签矩阵、外部资源链接以及双向关联与反向引用，使我能随时查看条目元属性与知识网络，而居中正文卷宗内不再有任何非正文项的干扰。

**Why this priority**: 这是本次重构的核心需求。目前详情页中标签、时间戳、外部链接和关联图谱全部混杂堆叠在正文容器（Article Binder）内；将所有元数据彻底剥离至左侧独立卡片面板，能够保证正文的纯粹性与元数据查找的高效性。

**Independent Test**: 打开任意包含完整元数据的条目详情页，验证居中正文容器内仅展示标题、摘要与正文文本，所有分类、时间、标签、外链与关联卡片均完整展示在左侧独立一体化档案大卡中。

**Acceptance Scenarios**:

1. **Given** 访客访问包含标签、外部链接和关联条目的详情页，**When** 页面加载完成时，**Then** 居中正文卷宗（Specimen Reading Binder）保持严格水平居中且仅呈现正文内容，左侧外边缘区域呈现单张一体化的元数据档案大卡（Metadata Dossier Panel）。
2. **Given** 访客查看左侧独立的元数据档案大卡，**When** 浏览卡片内容时，**Then** 卡片内通过工坊虚线分隔，有序展示条目的规范分类徽章、标本编号、收录与更新时间戳、标签矩阵、外部直达链接列表以及双向/反向引用图谱。
3. **Given** 访客查看居中正文卷宗，**When** 通读正文时，**Then** 正文区域仅保留大标题、标本提要与 Markdown 渲染主体，所有非正文元数据均不出现在正文卷宗内部。

---

### User Story 2 - 正文阅读区域的沉浸专注体验 (Priority: P1)

作为一名需要深度阅读长篇笔记、Prompt 指令或 Skill 文档的用户，我希望居中正文区域保持舒适干净的纸品排版（温润特种纸底色、舒适行高与合理的 65~75 字符黄金行宽），让注意力完全聚焦在文本与代码块上，免受任何穿插或附着元数据的分散。

**Why this priority**: 数字花园的核心价值之一是沉浸式阅读与工坊手账质感。完全剥离元数据后，居中正文区域得以回归纯粹的阅读体验。

**Independent Test**: 打开长篇 Note 或复杂 Prompt 条目，验证正文排版行宽在各种视口下均保持在舒适阅读区间，代码块软折行与复制功能正常，且正文视觉流不再被非内容属性打断。

**Acceptance Scenarios**:

1. **Given** 访客阅读长篇条目内容，**When** 滚动浏览居中正文时，**Then** 正文文本排版保持舒适行宽与行高，代码块安全展示一键复制控件且无遮挡。
2. **Given** 条目包含精炼的摘要提要，**When** 访客阅读文章顶部时，**Then** 摘要以醒目的标本提要框形式呈现于大标题下方，作为正文前置导读。

---

### User Story 3 - 多端响应式布局与顺畅阅读流 (Priority: P2)

作为在不同设备（桌面宽屏显示器、笔记本电脑、平板以及竖屏手机）上访问花园的用户，我希望详情页在桌面宽屏下呈现优雅的“居中正文 + 左侧外缘元数据面板”格局，并在移动窄屏下自动切换为“正文上方紧凑折叠档案卡”，确保在任何屏幕尺寸下都不会发生排版塌陷、相互遮挡或横向滚动。

**Why this priority**: 详情页是用户停留时间最长的页面，必须在宽屏与移动端均提供优质的版式与易读性。

**Independent Test**: 在桌面端（$\ge 1200\text{px}$）与移动端（$< 1200\text{px}$，如 375px、768px、1024px）之间缩放浏览器视口，验证布局平滑切换，窄屏下折叠卡片点击展开与收起正常运作，无任何元素溢出视口。

**Acceptance Scenarios**:

1. **Given** 访客在桌面宽屏（视口宽度 $\ge 1200\text{px}$）下浏览详情页，**When** 页面渲染时，**Then** 正文卷宗严格保持在视口中轴线居中，左侧外边缘空白区呈现一体化的元数据档案大卡（具备顶部粘性跟随效果）。
2. **Given** 访客在移动端与窄屏（视口宽度 $< 1200\text{px}$）下浏览详情页，**When** 页面渲染时，**Then** 布局自适应为单栏流式排列，居中正文上方呈现紧凑的手风琴档案卡（默认展示分类与标本编号，提供显式“展开完整档案 ▾”按钮）。
3. **Given** 访客在窄屏下点击“展开完整档案 ▾”，**When** 触发交互时，**Then** 卡片平滑展开完整标签矩阵、外部直达链接与关联图谱，再次点击可折叠收起。
4. **Given** 视口在不同尺寸之间连续缩放，**When** 跨越断点时，**Then** 页面布局平滑重排，无内容截断、无双滚动条且无横向溢出。

---

### User Story 4 - 元数据卡片内部的高效交互与知识导航 (Priority: P2)

作为一名在花园中搜寻相关工具、探索主题脉络的访客，我希望在独立的元数据卡片面板中能够便捷地与各个属性互动：点击标签跳转至首页探索对应分类、点击外部资源链接在新标签页直达原始网站、点击关联条目直接跳转至关联标本详情页。

**Why this priority**: 元数据面板不仅是静态属性展示，更是全站双向知识网络与外部资源的流转中枢。

**Independent Test**: 在元数据面板中依次点击各个标签徽章、外部资源链接以及双向关联条目卡片，验证所有超链接的导航行为符合预期且具有触控/悬停反馈。

**Acceptance Scenarios**:

1. **Given** 元数据卡片中展示了条目的标签列表，**When** 访客点击某个标签徽章时，**Then** 页面导航至探索页面并带上对应的筛选状态。
2. **Given** 元数据卡片中包含外部资源链接，**When** 访客点击外链项时，**Then** 浏览器在新标签页中安全打开该目标 URL（具备 `rel="noopener noreferrer"`）。
3. **Given** 元数据卡片中包含双向关联（Related）或反向引用（Backlinks），**When** 访客点击任意关联卡片项时，**Then** 顺畅导航至目标条目的 `/entries/<slug>/` 规范详情页。

---

### User Story 5 - 无障碍导航、焦点管理与静态可访问性 (Priority: P3)

作为一名使用键盘导航、屏幕阅读器或禁用 JavaScript 的用户，我希望页面具备语义化的无障碍标签结构，支持 `Tab` 键在返回按钮、正文内容、独立元数据卡片面板内的各交互触点之间逻辑移动，并在无 JS 环境下 100% 保持完全可读与可导航。

**Why this priority**: 遵循数字花园宪法中“静态优先、无障碍完备”的准则，确保独立卡片面板具备工业级的稳健性。

**Independent Test**: 使用键盘 `Tab` 键全程遍历详情页，验证焦点移动顺序符合逻辑、各交互元素高亮明显；在浏览器中禁用 JavaScript 刷新页面，验证正文与元数据面板完整静态输出（窄屏使用 HTML5 `<details>` 原生展开）。

**Acceptance Scenarios**:

1. **Given** 用户仅使用键盘 `Tab` 键导航详情页，**When** 焦点在正文与独立元数据卡片面板之间移动时，**Then** 焦点指示器清晰呈现双层高对比度轮廓，交互顺序符合逻辑。
2. **Given** 浏览器禁用 JavaScript，**When** 访问任意条目详情页时，**Then** 正文与独立元数据卡片面板由服务端完全渲染输出，窄屏折叠卡片基于原生 HTML 语义（如 `<details>` / `<summary>`）在无脚本下仍可自由展开阅读。

---

### Edge Cases

- **超宽屏幕（> 1600px）与中等屏幕（1200px ~ 1400px）下的左侧外缘定位**：在超宽屏下，左侧元数据面板紧贴居中正文卷宗的左边缘外侧，不至于因为视口过宽而飞到屏幕极左侧与正文割裂；在中等屏幕下保证左侧留白足以完整容纳面板（宽度约 260px~300px）。
- **极简条目（无标签、无外链、无关联条目）**：当条目未配置标签、未填写外链且无任何关联反链时，左侧元数据面板仅展示基础分类徽章、标本 ID 与收录/修订时间，自动隐藏空的外链与关联区块，严禁展示空白占位框。
- **超长标签文本与长外链名称**：当标签词条较长或外部链接标题字数较多时，元数据卡片内部文本自动安全软折行，严禁超出卡片边界或造成布局溢出。
- **超小屏幕设备（< 360px 宽度手机）**：所有卡片内边距等比微调，按钮与链接文字不被裁切，最小触控热区严格维持在 44px × 44px 以上。
- **弱动效偏好（prefers-reduced-motion）**：在系统开启减弱动效偏好时，卡片与按钮的悬停位移过渡及折叠手风琴展开动效完全关闭，直接呈现即时显隐。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 将条目详情页中的所有元数据（包括分类徽章、标本编号、首次收录日期、最近修订日期、标签矩阵、外部资源链接列表、双向关联条目以及反向引用）从正文容器中彻底剥离，统一组织于一个独立的**单张一体化元数据档案卡片面板（Unified Metadata Dossier Panel）**中。
- **FR-002**: 居中正文阅读容器（Specimen Reading Binder）MUST 保持在页面视口中轴线严格水平居中，且**仅承载纯正文内容**（大标题、摘要引言与 Markdown/MDX 渲染正文主体），严禁在正文卷宗内混杂任何非正文项。
- **FR-003**: 页面在桌面宽屏视口（$\ge 1200\text{px}$）下 MUST 将独立的元数据卡片面板放置于居中正文左侧的外边缘空白区域（Left Wing），并支持顶部粘性跟随（`position: sticky`），使长文阅读时元数据随行可见且不破坏正文居中视觉轴线。
- **FR-004**: 页面在窄屏与移动端视口（$< 1200\text{px}$）下 MUST 自动响应式切换为**正文上方紧凑折叠档案卡（Collapsible Dossier Accordion）**，默认展示分类类型与标本编号等核心标牌，并提供清晰的“展开/收起完整档案”交互，展开后完整呈现标签矩阵、外部链接与关联图谱。
- **FR-005**: 独立元数据卡片面板 MUST 采用单张一体化工坊档案大卡形态，内部使用工坊墨线/虚线标牌清晰分隔以下结构化信息分区（各分区按数据存在性动态渲染）：
  1. **标本档案与时序标牌**：展示条目大类徽章（Prompt/Skill/MCP/Website/Project/Note）、专属分类（如 Note Vol）、标本编号（Specimen ID）、首次收录日期与最近修订日期；
  2. **标签主题矩阵**：展示条目包含的全部标签，每个标签以硬边微胶带/印章徽章形态呈现，支持点击交互；
  3. **外部资源直达链接**（若配置）：展示带有外链图标与指示箭头的直达超链接列表；
  4. **知识图谱关联网络**（若存在）：展示双向关联（Related）与反向引用（Backlinks）条目卡片列表。
- **FR-006**: 元数据卡片面板的视觉设计 MUST 严格遵循 `docs/DESIGN.md` 中的俏皮野兽派规范（单张一体化纸卡容器、直角无圆角结构、纯黑墨线粗边框 $2.5\text{px} \sim 4\text{px}$、硬边实色偏移阴影 $4\text{px} \sim 8\text{px}$、工坊特种纸底色、统一线宽 SVG 线性图标，严禁原生 Emoji）。
- **FR-007**: 元数据卡片面板中所有可点击元素（外链、标签、关联条目、折叠触发器、返回上一页）在触控设备上的最小有效热区 MUST 达到 $44\text{px} \times 44\text{px}$，且在键盘聚焦（`focus-visible`）时呈现高对比度焦点轮廓环。
- **FR-008**: 页面 MUST 采用静态优先（Static-First）原则，在客户端无 JavaScript 环境下 100% 正常渲染正文与元数据面板，移动端折叠卡片采用原生语义（如 `<details>`）保证在无脚本环境下 100% 可展开查看。
- **FR-009**: 当条目缺少部分元数据（如无外链或无关联条目）时，元数据卡片面板 MUST 自动隐去对应空分区，保持面板紧凑完整，不显示无内容的空占位。
- **FR-010**: 详情页顶部的“返回上一页”操作条与标本编号标牌 MUST 保持清晰易用的导航指引。

### Key Entities *(include if feature involves data)*

- **Specimen Reading Binder (居中正文卷宗)**: 详情页的主正文容器实体，严格水平居中，专用于承载条目标题、标本摘要引言与 Markdown 长文渲染，遵循 65~75 字符黄金行宽与舒适排版规范。
- **Metadata Dossier Panel (左侧一体化元数据档案大卡 / 移动端折叠档案卡)**: 独立于正文卷宗的单张结构化档案大卡实体，在宽屏位于居中正文左侧外缘空白区，在窄屏位于正文上方作为折叠手风琴卡片，内部通过虚线分区承载标本身份徽章、时序记录、标签矩阵、外部资源链接与关联图谱网络。
- **Specimen Meta Entry (条目元数据载荷)**: 包含分类类型、标本 slug、收录日期、更新日期、标签列表、外链集合、双向关联引用集与反向引用集的数据结构。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 居中正文卷宗内纯正文呈现率达到 100%，所有非正文元数据均彻底剥离至独立元数据面板。
- **SC-002**: 桌面宽屏（$\ge 1200\text{px}$）下正文卷宗严格保持在屏幕中轴线居中，左侧独立元数据卡片面板在左外缘区域 100% 完整呈现且无视口横向溢出。
- **SC-003**: 移动端与窄屏（360px 至 1199px）下正文上方折叠档案卡 100% 正常显示并支持展开/收起，横向滚动条产生率为 0%。
- **SC-004**: 元数据面板内所有交互按钮、链接和标签在触控设备上的有效热区 100% 达到 $44\text{px} \times 44\text{px}$。
- **SC-005**: 客户端无 JavaScript 极限环境下，页面正文与元数据卡片面板完整渲染率达到 100%，移动端折叠面板在无脚本下仍可 100% 展开阅读。
- **SC-006**: 静态构建（`pnpm build`）与全站自动化测试套件 100% 绿灯通过，无类型错误与无障碍警告。

## Assumptions

- 详情页的数据结构直接复用现有的 Astro Content Collections（`src/content.config.ts`）及现有关联计算工具（`src/lib/entries.ts`），无需改动底层内容 schema。
- 条目规范访问路由保持为不可变的 `/entries/<slug>/`。
- 视觉风格完全继承 `docs/DESIGN.md` 与宪法中定义的俏皮野兽派与手账工坊规范（无圆角、粗墨边框、硬边阴影、特种纸基底）。
- 移动端手风琴折叠采用原生 HTML `<details>`/`<summary>` 或纯 CSS/微量静态脚本实现，保证渐进增强。
