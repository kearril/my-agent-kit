# Feature Specification: Entry Card Quick-View Modal (条目卡片速览大弹窗)

**Feature Branch**: `003-entry-preview-modal`

**Created**: 2026-08-26

**Status**: Draft

**Input**: User description: "当前，条目卡片点击则直接进入详情页，我需要添加一个新的功能：在点击条目卡片时，弹出一个大弹窗来显示，而不是直接进入条目详情。改变条目卡片的行为：点击该卡片则弹出弹窗，并且在卡片里添加一个按钮，保留进入详情页的入口。我的整体需求是这样。使用场景是：有些条目比较简短，希望能够通过弹窗卡片来速览。"

## Clarifications

### Session 2026-08-26

- Q: 本次速览大弹窗功能应在站点的哪些板块中生效？ → A: 仅在所有“卡片类型”的条目网格（Explore 探索区卡片与 Featured 精选收录卡片）生效；横条/流水行类型（Updates 打字机流水明细行、Notes 随笔卷宗行）不做弹窗，保持原有直接跳转。
- Q: 当条目内容或摘要较长、超出速览大弹窗的最大可视高度时，系统应如何处理超出部分的排版与交互？ → A: 采用视口高度受控（最大不超过 85vh）+ 内部主体区域独立纵向平滑滚动 + 头部与底部操作栏固定可见的设计，确保在长文或小屏下随时可快捷退出或跳转详情页。
- Q: 卡片内部的“直接进入详情页”独立入口应以何种视觉形态与位置呈现？ → A: 采用卡片底部右下角独立实体按钮形式（带有黑线边框、按压微位移与外链箭头提示，如“进入详情 ↗”），与卡片主体明确区分，防止误触。
- Q: 弹窗卡片与普通卡片、详情页长文的视觉与功能边界如何区分？ → A: 弹窗采用专门定制的“工坊速查卷宗夹（Workbench Quick Dossier）”形态，展示完整 Markdown 正文与指令、外链直达甲板以及代码/Prompt 一键复制按钮，既不拉大普通卡片，也不复制详情页复杂导航与关联甲板。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 点击条目卡片快速唤起大弹窗速览 (Priority: P1)

作为一名在数字花园中浏览、搜索工具和笔记的访客，我希望在点击任意条目卡片主体时，页面原地弹出一个具有手账工坊质感的大卡片速览弹窗（Quick-View Modal），展示该条目的标题、分类徽章、详细摘要、标签矩阵及时间等核心信息，以便在不离开当前探索流与筛选条件的情况下，快速阅读简短内容或评估条目价值。

**Why this priority**: 这是本次特性的核心诉求。许多条目（如简短 Prompt、工具推荐、Skill 摘要）篇幅精炼，整页跳转加载会打断探索连贯性；原地速览弹窗能够在保持当前上下文的同时提供即时阅读体验。

**Independent Test**: 在探索列表或卡片网格中点击任意条目卡片主体，验证是否在当前页面即时弹出大卡片速览弹窗，弹窗内完整呈现该条目的核心内容与元数据，且背景浏览位置与筛选条件保持不变。

**Acceptance Scenarios**:

1. **Given** 访客在卡片网格区域浏览条目卡片，**When** 鼠标点击卡片主体或使用键盘聚焦并按下回车时，**Then** 原地唤起大卡片速览弹窗，展示该条目的序号、类型徽章、标题、完整摘要、标签列表与更新日期。
2. **Given** 访客在已筛选或搜索特定关键词的状态下，**When** 唤起并随后关闭速览弹窗时，**Then** 当前的搜索关键词、类型过滤、标签选择与列表滚动位置完全保留，无任何页面重新加载或状态丢失。
3. **Given** 弹窗处于打开状态，**When** 访客浏览弹窗内容时，**Then** 弹窗视觉风格符合直角硬边纸卡（无圆角、粗黑边框、硬边实色阴影、工程纸底色），排印间距舒适易读。

---

### User Story 2 - 卡片保留直接进入详情页的独立入口 (Priority: P1)

作为一名明确需要查看条目完整页面、复制长篇代码或获取规范永久链接（Canonical URL）的访客，我希望在条目卡片底部右下角拥有一个独立、清晰可见的实体操作按钮（如“进入详情 ↗”），允许我直接一键导航至该条目的规范详情页 `/entries/<slug>/`，无需先打开弹窗再二次点击。

**Why this priority**: 改变卡片默认点击行为后，必须保留直达完整详情页的高效路径，满足不同意图（“轻量速览” vs “深度阅读/新标签页打开”）的用户需求。

**Independent Test**: 点击卡片底栏右下角的“进入详情 ↗”专属实体按钮，或使用键盘聚焦该按钮并触发，验证浏览器直接导航进入对应条目的规范详情页 `/entries/<slug>/`。

**Acceptance Scenarios**:

1. **Given** 访客在条目卡片底栏看到“进入详情 ↗”专属实体按钮，**When** 点击该按钮时，**Then** 浏览器直接导航跳转至该条目的详情页 `/entries/<slug>/`，不触发速览弹窗。
2. **Given** 访客在桌面端使用鼠标中键或右键“在新标签页中打开”，**When** 针对该独立实体按钮链接进行操作时，**Then** 浏览器正常在新标签页打开该条目的规范 URL。
3. **Given** 访客使用键盘 `Tab` 键遍历卡片，**When** 焦点移动至卡片底部的“进入详情 ↗”按钮时，**Then** 按钮呈现清晰的键盘焦点指示环，且按下 `Enter` 键可直接进入详情页。
---

### User Story 3 - 弹窗内完整速览、快捷操作与流转能力 (Priority: P2)

作为一名正在通过弹窗速览条目的访客，在阅读完摘要或元数据后，我希望在弹窗内部能够一键流转前往完整详情页、点击标签进行快速筛选或复制关键信息，获得顺畅的后续操作支持。

**Why this priority**: 弹窗不仅是展示终点，更是从“快速扫描”过渡到“深入探索”或“内容使用”的关键触点。

**Independent Test**: 在打开的速览弹窗内点击“查看完整文章 / 前往详情页”主操作按钮，验证是否无缝跳转至该条目详情页；测试弹窗内的辅助操作（如点击标签、关闭等）。

**Acceptance Scenarios**:

1. **Given** 访客在速览弹窗中阅读条目，**When** 点击弹窗底部的“前往完整详情页”主按钮时，**Then** 页面顺畅导航至 `/entries/<slug>/` 详情页。
2. **Given** 弹窗内展示了条目的标签列表，**When** 访客点击某个标签时，**Then** 可关闭弹窗并将外部探索列表联动过滤为该标签（或流转至对应筛选视图）。
3. **Given** 条目包含关键摘要或简短指令，**When** 访客在弹窗内选中文本时，**Then** 文本可选且排版清晰，无误触发关闭弹窗。

---

### User Story 4 - 完备的无障碍、焦点管理与便捷退出机制 (Priority: P2)

作为一名使用键盘导航、屏幕阅读器或触控设备的用户，我希望在弹窗打开时页面背景滚动被锁定、键盘焦点被安全捕获在弹窗内，并支持通过按下 `Esc` 键、点击遮罩背景或点击关闭按钮轻松退出弹窗，且退出后焦点精准恢复到原卡片。

**Why this priority**: 模态弹窗必须具备完善的焦点陷阱与退出机制，避免焦点丢失、背景穿透滚动或键盘用户无法退出的严重体验与无障碍问题。

**Independent Test**: 打开速览弹窗后，测试按 `Esc` 键、点击半透明遮罩背景、点击右上角关闭按钮 3 种方式是否均能平滑退出弹窗；测试 `Tab` 键在弹窗内部循环聚焦；测试弹窗关闭后焦点是否精准恢复至之前点击的卡片。

**Acceptance Scenarios**:

1. **Given** 速览弹窗已打开，**When** 访客按下键盘 `Esc` 键时，**Then** 弹窗即时关闭，页面背景滚动恢复，键盘焦点自动回到触发该弹窗的卡片。
2. **Given** 速览弹窗已打开，**When** 访客使用鼠标或触控点击弹窗外部的暗色遮罩层时，**Then** 弹窗平滑关闭，无残留遮罩。
3. **Given** 速览弹窗处于打开状态，**When** 用户尝试滚动页面时，**Then** 底层背景页面滚动被严格锁定，仅弹窗内部长内容允许独立纵向滚动。
4. **Given** 用户使用键盘 `Tab` 键在弹窗内导航，**When** 焦点到达弹窗内最后一个可交互元素并再次按下 `Tab` 时，**Then** 焦点循环回到弹窗内第一个可聚焦元素（如关闭按钮），不泄露至背景页面。

---

### User Story 5 - 无脚本环境下的渐进增强与静态回退 (Priority: P3)

作为一名在网络不佳、脚本加载受阻或主动禁用 JavaScript 环境下访问数字花园的用户，我希望条目卡片依然具备基础的超链接导航能力，点击能够直接进入详情页，确保站点核心内容 100% 可达。

**Why this priority**: 遵循数字花园宪法中“静态优先、渐进增强”的原则，确保公开内容在无 JS 极限环境下仍具备完整可访问性。

**Independent Test**: 在浏览器禁用 JavaScript 的情况下访问页面，点击条目卡片，验证其直接作为普通超链接跳转至对应条目详情页。

**Acceptance Scenarios**:

1. **Given** 客户端 JavaScript 未加载或被禁用，**When** 访客点击条目卡片时，**Then** 卡片直接作为标准 HTML 超链接导航跳转至该条目的 `/entries/<slug>/` 页面。

---

### Edge Cases
- **超长摘要与长内容溢出**：当条目摘要或说明字数较多时，速览大弹窗最大高度限制在视口高宽安全区内（如最大 `85vh`），头部标题栏与底部操作栏保持固定置顶/置底，中间主体内容区启用舒适的内部纵向平滑滚动，严禁产生双滚动条或内容撑破弹窗边界。
- **超小屏幕设备（< 480px / 360px 宽度手机）**：弹窗自适应为贴底便签大卡片或近全屏视口，边距与字体等比收紧，关闭按钮和底部操作按钮的触控热区严格维持在 44px × 44px 以上。
- **高频连击与快速按键**：用户极短时间内连续多次点击卡片或在弹窗刚唤起时快速按下 `Esc` 键，弹窗状态平稳切换，不会出现多重遮罩叠加、动画中断卡死或页面无法交互的死锁状态。
- **减弱动效偏好（prefers-reduced-motion）**：在系统开启减弱动效偏好时，弹窗的展开与收起完全移除位移和缩放过渡动画，直接进行即时显隐或纯透明度切换。
- **右键在新标签页打开**：卡片内的“进入详情”专属入口必须保留标准语义化 `href` 属性，确保右键或中键点击能正常触发浏览器原生在新标签页打开详情页的行为。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 将所有卡片类型条目网格（包括 Explore 探索区域卡片与 Featured 精选收录卡片）的卡片主体点击交互调整为**原地唤起速览大弹窗（Quick-View Modal）**；横条/流水行列表（如 Updates 打字机流水行、Notes 随笔卷宗行）保持原有直接跳转详情页的默认行为。
- **FR-002**: 每张参与速览的条目卡片（Explore 与 Featured 网格卡片）底栏右下角 MUST 提供一个独立、显式且可聚焦的**“进入详情 ↗”实体按钮**（带有黑线边框与触控反馈），允许用户一键直接导航至 `/entries/<slug>/` 规范详情页，且与卡片主体点击区有效区隔。
- **FR-003**: 速览大弹窗 MUST 采用专属的“工坊速查卷宗夹（Workbench Quick Dossier）”视觉形态（顶部牛皮/金属夹具梁、金属铆钉装饰、专属类型标牌、直角无圆角、粗墨线边框与实色阴影），最大高度限制在视口安全范围内（$\le 88\text{vh}$），头部与底部操作栏固定置顶/置底，内部主体区支持独立纵向滚动，完整呈现条目标题、标本提要、外部直达链接甲板、Markdown 完整正文与带一键复制控件的工程浅色代码/提示词块。
- **FR-004**: 速览大弹窗内部 MUST 包含一个直达该条目完整详情页的主操作按钮（如“前往完整档案册 ↗”），支持在速览后平滑流转进入长文阅读。
- **FR-005**: 速览大弹窗 MUST 提供 3 种独立的关闭方式：
  1. 点击弹窗右上角显式的关闭按钮；
  2. 点击半透明遮罩背景层；
  3. 按下键盘 `Esc` 键。
- **FR-006**: 速览大弹窗激活时，系统 MUST 自动锁定底层页面背景滚动（Body Scroll Lock），杜绝背景穿透滚动；弹窗关闭后 MUST 精准恢复页面原有滚动状态。
- **FR-007**: 速览大弹窗 MUST 具备完善的无障碍焦点管理（Focus Trap & Focus Restoration）：打开时焦点自动移入弹窗内部首个可交互元素，打开期间键盘焦点在弹窗内循环，关闭后焦点 MUST 自动恢复至触发该弹窗的卡片元素。
- **FR-008**: 条目卡片上的直接详情入口与弹窗内所有交互按钮 MUST 具备可访问名称，支持键盘 `Tab` 遍历，并在 `focus-visible` 时呈现清晰的双层硬边高对比度焦点指示环。
- **FR-009**: 在客户端 JavaScript 未加载或被禁用的环境下，条目卡片 MUST 保持渐进增强静态回退（Graceful Static Fallback），作为标准超链接直接访问条目详情页。
- **FR-010**: 速览大弹窗在移动端（< 768px 及 360px 小屏）MUST 实现响应式自适应布局，内容超出视口时支持弹窗内平滑纵向滚动，所有按钮触控热区 MUST 不小于 44px × 44px。
- **FR-011**: 弹窗的展开与收起动效 MUST 严格遵守 `prefers-reduced-motion: reduce` 系统偏好，在开启弱动效时禁用所有旋转与位移动画。
- **FR-012**: 弹窗及卡片内的所有装饰与功能图标 MUST 使用统一线宽的 SVG 线性图标，严禁使用原生 Emoji 作为功能或装饰符号。

### Key Entities *(include if feature involves data)*

- **Entry Specimen Card (条目标本卡片)**: 资产列表中展示条目概要的卡片实体，包含“卡片主体区域”（点击触发速览大弹窗）与“底栏右下角直达按钮”（点击直接导航至条目规范详情页）两个明确区隔的独立交互触点。
- **Quick-View Modal (速览大弹窗)**: 悬浮于当前页面之上的模态预览容器，包含半透明遮罩层、直角硬边纸卡主体（高度 $\le 85\text{vh}$）、头部标题与类型徽章栏、完整摘要内容区、标签矩阵以及固定于底部的操作工具栏。
- **Modal Session State (弹窗会话与焦点状态)**: 管理当前激活条目的数据引用、弹窗开闭布尔状态、背景滚动锁定标记以及触发源 DOM 节点焦点引用的会话状态实体。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 访客点击任意条目卡片主体后，速览大弹窗在 100ms 内流畅呈现，当前页面浏览位置、搜索关键词与筛选标签 100% 保持不变。
- **SC-002**: 访客点击条目卡片上的“进入详情”专属入口，可在 1 次点击内直接启动向规范详情页（`/entries/<slug>/`）的导航。
- **SC-003**: 弹窗支持通过 `Esc` 键、遮罩点击、关闭按钮 3 种独立方式在 100ms 内迅速关闭，关闭后键盘焦点 100% 准确恢复至触发卡片。
- **SC-004**: 弹窗打开期间，底层页面背景滚动穿透发生率为 0%（滚动锁定生效）。
- **SC-005**: 弹窗内所有交互按钮（关闭、跳转详情、标签点击）在触控设备上的有效热区 100% 达到 44px × 44px 以上。
- **SC-006**: 在禁用 JavaScript 环境下，条目卡片 100% 保持为可用超链接，点击可顺利访问对应条目详情页。
- **SC-007**: 静态站点构建（`pnpm build`）与全站自动化测试套件 100% 绿灯通过，无类型错误与无障碍控制台警告。

## Assumptions

- 探索与资产展示列表（`ExploreIsland.tsx`）及精选收录展架（`FeaturedSection.astro`）等卡片网格作为速览大弹窗的生效载体；横条流水行（Updates、Notes）保持标准超链接。
- 弹窗中展示的条目数据直接复用现有的 Explore 索引字段（包含标题、完整摘要、分类类型、标签集、时间戳及规范路径），无需发起额外的客户端异步网络请求即可实现毫秒级快速弹出。
- 弹窗的视觉风格完全继承 `docs/DESIGN.md` 与宪法中定义的俏皮野兽派与手账工坊规范（方案 A）。
- 规范路由 `/entries/<slug>/` 保持为所有公开条目的唯一不可变永久详情地址。
