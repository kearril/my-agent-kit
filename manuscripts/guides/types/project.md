# Project（工程项目/开源工具）条目写作规范

## 一、 定位与原则

- **内容形态**：面向开源工具、软件工程套件或框架项目的**客观资产介绍、架构机制与交互指南**。
- **标题前缀规范**：
  - 命令行工具/轻量工具：`[开源工具] <名称>：<副标题>`
  - 完整应用/客户端/大型软件：`[开源软件] <名称>：<副标题>`
  - 综合型项目或不易严格界定者：`[开源项目] <名称>：<副标题>`
  - 非开源项目/商业产品：视情况选择 `[商业软件]`、`[效率工具]` 等合理前缀。
- **写作重心**：聚焦在“项目定位与设计概述”、“命令交互与工作流实践”、“核心架构与功能特性”以及“生态集成与专属特性”。
- **深度思考分流**：作者个人的长期实践心得、深层技术对比沉淀至 `note` 类型随笔，不在此类条目中过度发散。

---

## 二、 正文标准四段式骨架

```markdown
> 本条目基于官方仓库 `<owner>/<repo>` **<版本号/Commit>** 进行梳理与收录。

## 一、 项目定位与设计概述

- 阐述该项目解决的核心痛点（背景、现有生态碎片化/低效场景）。
- 明确项目定位与核心设计理念（如何抽象、如何统一规范、单一事实来源等）。

## 二、 命令交互与工作流实践

- **运行方式与依赖前提**：运行环境（Node.js/Go/Rust等）、调用方式（npx/brew/curl等）。
- **核心操作与多源解析**：安装/初始化核心指令、参数解析与常见源格式。
- **即时试用与单次执行**：免安装运行或管道流转能力（若有）。
- **资产维护与生命周期指令**：查看、检索、更新、卸载与脚手架指令清单。

## 三、 核心架构与功能特性

- **作用域模型**：项目级与全局级等边界划分。
- **分发与同步机制**：缓存、符号链接（Symlink）、物理拷贝等底层实现。
- **版本锁定与清单管理**：Lockfile、配置清单与确定性复现机制。
- **跨环境/跨工具兼容桥接**：通用路径归一化与专有路径映射策略。

## 四、 生态集成与专属特性

- **官方注册表/索引平台**：官方平台或社区目录配套（若有）。
- **特有功能/元能力**：如内置元技能、自发现机制、自动化扩展点。
- **兼容生态矩阵**：支持的主流宿主环境、客户端或依赖库概况。
```
