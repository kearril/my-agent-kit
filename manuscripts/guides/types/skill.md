# Skill（Agent 技能）条目写作规范

## 一、 定位与原则

- **内容形态**：面向编码 Agent 技能集、工程守则或方法论套件的**客观资产介绍与使用指南**。
- **写作重心**：聚焦在“它是什么”、“治理的核心问题”、“安装配置与工程流转”以及“核心资产清单”。
- **深度思考分流**：作者个人的长期实践心得、深层架构思考沉淀至 `note` 类型随笔，不在此类条目中过度发散。

---

## 二、 正文标准四段式骨架

```markdown
> 本条目基于官方仓库 `<owner>/<repo>` **<版本号/Commit>** 进行梳理与收录。

## 一、 框架定位与设计概述

- 说明该技能集的作者/机构背景与核心理念。
- 阐明其技术形态（一组模块化的 `SKILL.md` 规则、触发机制如 User-invoked 与 Model-invoked 等）。

## 二、 核心问题与治理目标

- 梳理 Agent 在没有该技能约束时面临的典型失控场景（如需求模糊盲目动工、凭猜测打补丁、长会话压缩失忆、代码缺乏测试等）。
- 阐述该技能集如何通过机制设计从流程上规避上述问题。

## 三、 安装配置与工程工作流

### 1. 安装配置

- 重点展示基于 `skills-cli` 的通用模式安装指令（项目安装与全局安装）。
- 简要说明一次性初始化指令（若有）以及原生客户端（Claude Code、Cursor 等）的适配支持。

### 2. 标准交付流水线

- 梳理 Agent 在实际执行开发任务时的端到端流转阶段（如 5 阶段或 7 阶段工程闭环），每阶段明确核心动作与对应触发的技能。

## 四、 核心技能资产索引

- 按照功能领域（如“测试与排错”、“流程与协作编排”、“元技能与引导”）对仓库内的技能资产进行分类罗列。
- 每个技能配以 1 至 2 句精炼的功能边界说明。
```
