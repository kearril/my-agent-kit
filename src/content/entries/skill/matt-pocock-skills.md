> 本条目基于官方仓库 `mattpocock/skills` **v1.2.3** 版本进行梳理与收录。

## 技能定位

许多全流程 AI 编程框架倾向于直接接管整个软件开发流水线。这种做法虽然规范，但往往把开发过程封装成了黑盒，一旦某个环节执行出错，开发者很难介入排查。

TypeScript 工程师 Matt Pocock 开源的这套技能集走了另一条路线：把传统软件工程里沉淀下来的实践（测试驱动开发、领域驱动设计、深度模块封装、代码坏味道审查等）拆解成一个个短小、独立且易于魔改的 `SKILL.md` 文件。它的核心目标是解决 AI 编程中常见的四类失控：

1. **需求理解走样**：通过多轮反向提问（Grilling）在动工前把所有边界分支问清楚；
2. **上下文过载与术语混乱**：通过维护项目领域词典（`CONTEXT.md`）统一名词，用精准术语替代长篇累牍的背景解释；
3. **生成的代码无法运行**：引入 TDD（红灯-绿灯-重构）与结构化排错机制，用测试为模型提供即时反馈；
4. **代码库退化成混乱泥球**：推行深度模块设计（小接口大实现），并定期静态扫描代码库寻找架构重构机会。

## 安装与初始化

使用 `skills-cli` 将整套技能以通用模式安装到当前项目：

```bash
npx skills add mattpocock/skills -a universal
```

安装完成后，在目标项目内先运行一次初始化指令：

```text
/setup-matt-pocock-skills
```

该指令会引导你确认三项配置：项目使用哪种工单系统（GitHub Issues、Linear 或本地文件）、分拣任务时使用的标签命名，以及生成的文档保存目录。

## 通用开发流程

在实际开发一个新功能或进行复杂重构时，这套技能推荐按以下 5 个阶段推进：

1. **需求拷问与术语沉淀**：
   - 当你产生一个新需求时，先不要直接让 Agent 编码，而是运行 `/grill-with-docs`。
   - Agent 会对你进行多轮极限反向提问，挖清所有交互边界与异常分支，同时将新出现的专有名词写入项目领域词典（`CONTEXT.md`）并生成 ADR 架构决策记录。
2. **规范固化与任务拆解**：
   - 讨论达成共识后，运行 `/to-spec` 将对话结果一键沉淀为结构化需求规范，并同步至 Issue 跟踪系统。
   - 接着运行 `/to-tickets`，把规范自动切分为带有前置依赖关系的原子任务卡（超大型工程则使用 `/wayfinder` 绘制决策依赖地图）。
3. **测试驱动编码实现**：
   - 运行 `/implement` 驱动 Agent 读取任务卡分步编写代码。
   - 在编码过程中，Agent 会自动调用底层的 `tdd` 技能，严格遵循“编写失败测试 $\to$ 编写最小通过代码 $\to$ 重构优化”的红绿灯循环，避免盲写无测试代码。
4. **双轴审查与代码提交**：
   - 功能编写完成后，系统会自动调用 `code-review` 技能，由两个互不干扰的独立子 Agent 分别检查“代码坏味道”和“是否忠实还原工单”。
   - 确认无问题后完成 Git 提交（若遇合并冲突可调用 `resolving-merge-conflicts`）。
5. **定期架构巡检**：
   - 每隔几天运行一次 `/improve-codebase-architecture`，静态扫描代码库的复杂度与模块深度，生成重构建议报告，抑制 AI 极速编码带来的软件熵增。

## 工程开发技能（Engineering）

### 1. 需求澄清、领域建模与架构治理

- `/grill-with-docs`：在动手前对开发者进行深度多轮提问，挖尽所有设计分支，同时自动更新项目的领域词典（`CONTEXT.md`）与架构决策记录（ADR）。
- `domain-modeling`（模型自调）：在对话中主动提炼和校准业务专属术语，用统一语言消除上下文歧义并减少 Token 消耗。
- `codebase-design`（模型自调）：在编写代码时遵循深度模块设计原则，要求在简单干净的接口背后封装复杂逻辑，并确保接口可测试。
- `/improve-codebase-architecture`：静态扫描当前代码库，寻找可以进一步下沉封装的模块候选，生成可视化的 HTML 诊断报告供开发者挑选重构。

### 2. 任务规划与工单流转

- `/to-spec`：将当前对话中已经讨论清晰的内容直接整理成需求规范，并同步发布到工单系统。
- `/to-tickets`：把任何方案、规范或长对话切分成一组带有前置依赖与阻塞关系的原子任务卡。
- `/wayfinder`：用于处理超出单个 Agent 会话容量的超大型工程，在工单系统中建立决策依赖地图，协助开发者按拓扑顺序逐个攻克。
- `/triage`：按照状态机规则在工单系统中流转和分拣 Issue。
- `/ask-matt`：技能路由器，当你面对复杂场景不知道该调用哪个技能时，描述现状即可获得针对性的流程建议。

### 3. 编码实现、质量守门与协作

- `/implement`：驱动代码实现的主指令，根据工单或规范按步骤编写代码，并在每个关键节点串联 TDD，最终在提交前调用独立审查。
- `tdd`（模型自调）：推行严格的测试驱动开发，按“编写失败测试 $\to$ 编写最小通过代码 $\to$ 重构优化”的节奏推进。
- `diagnosing-bugs`（模型自调）：针对疑难 Bug 和性能回退的六步诊断循环：建立红灯测试用例 $\to$ 最小化复现 $\to$ 提出假设 $\to$ 埋点插桩验证 $\to$ 修复代码 $\to$ 回归测试。
- `code-review`（模型自调）：双轴并行审查代码变动，分别由独立的子 Agent 审查代码规范（代码坏味道基线）和需求一致性（是否忠实还原工单），互不干扰。
- `resolving-merge-conflicts`（模型自调）：逐块分析 Git 合并或变基冲突，追溯两侧分支的提交意图并化解冲突，严禁直接放弃。

### 4. 原型与技术探索

- `prototype`（模型自调）：快速构建探索性的单文件 HTML 原型，或在同一路由下构建多个可切换的 UI 方案以验证交互设计。
- `research`（模型自调）：让后台子 Agent 针对可信的一手资料开展技术调研，在项目中生成带有来源引用的 Markdown 调研备忘录。
- `wizard`（模型自调）：生成交互式的 Shell 引导脚本，协助人类完成云资源配置、密钥填写或数据迁移等必须人工介入的操作。

## 流程与协作效率技能（Productivity）

- `/grill-me`：纯方案与逻辑层面的极限反向提问，不涉及代码生成，专门用于理清思路和发现漏洞。
- `grilling`（底层原子）：作为可复用的提问引擎，驱动 `grill-me`、`grill-with-docs`、`wayfinder` 等多个技能的追问逻辑。
- `/handoff`：将当前会话的核心决策与进展浓缩为交接文档，方便在开启新会话时无缝传递上下文。
- `/wait-what`：当 Agent 输出让人难以理解的抽象内容时，命令它结合项目词汇表，用直白大白话重新阐述。
- `/to-questionnaire`：将无法独自决定的技术分歧转换为结构化的 Markdown 调查问卷，方便异步发给相关人员收集反馈。
- `/teach`：将当前工作目录作为互动练习沙盒，跨多个会话分步讲解复杂的技术概念。
- `writing-for-agents`（模型自调）：规范为 Agent 编写文档（如技能定义、系统守则）的格式与指针标准。

## 触发机制设计

这套技能体系在触发机制上分为两层：

- **User-invoked（用户显式指令）**：以 `/` 开头（如 `/grill-with-docs`、`/implement`），由开发者主动输入以发起流程或编排任务；
- **Model-invoked（模型自主调用）**：不带 `/` 符号（如 `tdd`、`diagnosing-bugs`、`code-review`），由 Agent 在执行任务时根据实际场景自主判断并调用。
